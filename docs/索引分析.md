# 索引分析

实测环境：MySQL 8.0.46；Orders 830 行，Products 77 行。完整执行计划见 `explain-results.json`，SQL 位于 `sql/course_demo.sql`。rows 是优化器估计扫描行数。

| 查询 | type | key | rows |
| --- | --- | --- | --- |
| 订单日期范围：2018-04-01 至 2018-05-01 前 | range | idx_orders_date | 77 |
| LEFT(OrderDate,7) = '2018-04' | ALL | 无 | 830 |
| 商品 CategoryID = 1 | ref | CategoryID（原外键索引） | 12 |
| ProductName LIKE 'Ch%' | range | idx_products_name | 6 |
| ProductName LIKE '%Ch%' | ALL | 无 | 77 |

# 解释

订单日期原始类型为 TEXT，扩展 SQL 对前 10 个字符建立前缀索引，完整覆盖 ISO 日期 `YYYY-MM-DD`。页面日期筛选采用左闭右开范围，直接比较列值，从而允许范围扫描。对列应用 LEFT 函数的示例会全表扫描，因此该函数仅用于销售月份分组，不放在页面的日期过滤条件中。

分类与供应商外键的支撑索引已经由源数据导入创建，扩展脚本读取 information_schema.statistics，复用以目标列开头的等效索引。再次执行扩展不会额外增加重复索引。

商品名称原始类型为 TEXT，对前 120 个字符建立索引。名称前缀查询可利用范围扫描；包含匹配的前导 `%` 破坏普通 B-tree 索引的可搜索前缀。界面的名称搜索按用户习惯提供包含匹配，在本数据规模下扫描 77 个商品成本可控，并未误称该搜索一定走索引。

EXPLAIN 支持验证访问路径，不能直接换算为执行时间或性能提升倍数。计划会随数据量、选择性、统计信息和 MySQL 补丁变化；扩大数据规模时应重新执行 EXPLAIN，再决定是否增加组合索引或专门的搜索方案。
